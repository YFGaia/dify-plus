## 3. getClientLoginFallback 回归（合并记录 TODO 5）

- 落点集中在 `web/utils/login-redirect.ts::getClientLoginFallback`，fork 值
  `/explore/apps-center-extend`（上游 `/`）。调用点共 9 个文件：
  Console 侧 `signin/utils/post-login-redirect.ts`（signin 全链共用）；
  webapp 侧 `webapp-signin/page.tsx`、`check-code/page.tsx`、`components/{sso-auth,
  mail-and-code-auth,mail-and-password-auth,external-member-sso-auth}.tsx`、
  shareLayout `components/splash.tsx`。除 `webapp-signin/page.tsx` 为 fork 修改版外，其余 7 个
  webapp 文件与上游逐字节一致。
- 行为分析结论：**一致且符合 fork 语义**。fallback 仅在无有效 redirect target 时生效；上游落点
  `/` 在 fork 里渲染 explore AppList（同为 Console 页），fork 落点是 fork 首页应用中心——两者
  同一风险等级，且 fork「WebApp 复用 Console 登录态」模型下 webapp 用户即 Console 用户。
  有效 redirect 永远优先，webapp 深链回跳不受影响。
- 随之把 5 个上游 spec 的 fallback 断言适配为 fork 语义（共 11 处断言，均加 extend 注释）：
  `utils/__tests__/login-redirect.spec.ts`(1)、`signin/utils/__tests__/post-login-redirect.spec.ts`(6)、
  `signin/__tests__/normal-form.spec.tsx`(2)、`signin/check-code/__tests__/page.spec.tsx`(1)、
  `signin/invite-settings/__tests__/page.spec.tsx`(1)。
- **Phase 6 人工回归项**：独立 basePath 部署的纯 webapp 场景下，无 redirect 登录后的落点体验
  （与上游 `/` 同类，但值得目测一次）。
