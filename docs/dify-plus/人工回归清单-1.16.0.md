## 1. 登录与三方认证

### 1.1 Console 邮箱密码登录与默认落点【P0】

背景：上游 1.16.0 登录改造（password Base64 + Cookie/CSRF 会话）+ fork 落点语义集中到
`getClientLoginFallback`（`/explore/apps-center-extend`）。

- 步骤：
  1. 无登录态打开 Console，用邮箱密码登录；
  2. 登录成功后观察落点；退出登录再带深链访问任一应用页，登录后观察回跳；
  3. 登录后随意做一次写操作（如改应用名），确认无 401/CSRF 报错。
- 预期：
  - 明文密码在 UI 正常登录（前端自动 Base64，用户无感）；
  - 无 redirect 时默认落点为**应用中心** `/explore/apps-center-extend`；
  - 带深链时优先回跳深链（fallback 不覆盖有效 redirect）；
  - 写操作正常（浏览器自动带 Cookie + `X-CSRF-Token`）。

### 1.2 钉钉登录【P0，需真实凭据】

背景：钉钉链路独立于 fork 文件（`ding_talk_extend.py` / `services/ding_talk_extend.py`），
本轮未被上游波及，但 Phase 4 修复了其新用户注册路径的两处 session TypeError（修复 #3），
且登录按钮组件本轮做了 i18n/lint 适配——需整链回归。

- 前置：系统管理 → 系统集成 → 钉钉配置已保存真实 corp_id/client_id 等并启用。
- 步骤：
  1. 登录页点击钉钉登录，完成扫码/免登授权；
  2. 用一个**从未登录过**的钉钉账号走一遍（覆盖新用户注册路径）；
  3. 在钉钉容器内打开（如适用）确认自动登录逻辑。
- 预期：老用户直接登录并落应用中心；**新用户注册成功不报 500**（TypeError 修复点）；
  账号信息（姓名/邮箱）正确；`account_money_extend` 自动建默认额度记录。

### 1.3 OAuth2 / casdoor 登录与回跳【P0，需真实凭据】

背景：挂点 10 本轮重挂——上游新增 `_get_redirect_target(redirect_url)` 同源回跳，fork 的
casdoor `id_token` 追加其后；Phase 4 修复了 `id_token=None` 污染非 casdoor 回跳 URL 的缺陷。

- 前置：系统管理 → 系统集成 → OAuth2 配置已保存真实端点/凭据并启用。
- 步骤：
  1. 登录页点击 OAuth2 登录，完成授权，观察回跳 URL 与落点；
  2. casdoor 场景：确认回跳 URL 带 `id_token=<非空值>`，且登出（`is_custom_auth2_logout`）
     链路可用；
  3. 若同时启用 GitHub/Google 等上游 OAuth，观察其回跳 URL。
- 预期：授权后正确登录并落应用中心（或深链）；casdoor 回跳 URL 含非空 `id_token`；
  **非 casdoor 的 OAuth 回跳 URL 不含 `id_token=None` 尾巴**（修复 #4 验证点）；
  带 `redirect_url` 的登录发起能同源回跳。

### 1.4 webapp-signin（WebApp 复用 Console 登录态）【P0】

背景：fork「WebApp 必须带 Console 登录态」模型 + 上游 loginRedirect 安全跳转体系合并；
`checkConsoleLoginStatus` 前置检查为 fork 新逻辑。

- 步骤：
  1. 浏览器 A（已登录 Console）打开某 WebApp 公开链接：应直接进入应用（复用登录态，
     可见短暂 Loading）；
  2. 浏览器 B（无 Console 登录态）打开同一链接：应被引导到 webapp-signin 登录，
     登录完成后回到该 WebApp；
  3. 品牌定制开启时确认登录页欢迎语隐藏（fork 语义）；
  4. 独立 basePath 部署的纯 webapp 场景（如有）：无 redirect 直接登录，目测落点体验
     （现指向 Console 应用中心，与上游落 `/` 同风险级——Phase 3b 遗留目测项）。
- 预期：登录态复用无死循环；未登录发消息被 401 拦截（`WebAuthRequiredErrorExtend`）；
  深链回跳不受 fork fallback 影响。

## 4. 系统管理三页 UI【P0】

背景：Phase 6 已完成 API 级冒烟（Cookie+CSRF 下全部 200/201）；本节验证**浏览器端表单与
运行时契约链路**（`consoleQuery.systemManage.*` 查询键、`X-Login-Config-Token` header

迁移 + oxlint 修复（a11y 改造、AlertDialog 替换 confirm），需目测无回归。

- 预期：**仅 owner** 渲染「系统管理」入口（admin 亦不渲染——前端裁剪比后端门禁更严，
  属既有语义）；普通成员直接输 URL 访问后端接口被 `system_admin_required_extend` 拒绝。

### 4.2 用户额度管理【P0】

### 4.3 系统集成（钉钉 / OAuth2 / 邮箱 API / 转发 Token）【P0，test 类接口需真实凭据】

- 步骤：
  1. 钉钉与 OAuth2 配置页：填写、保存、启用/禁用开关往返一次；点击**连接测试**类按钮
     （需真实第三方凭据，Phase 6 未冒烟的唯一后端面）；

     `confirm()` 换成 dify-ui 组件的改动点）。
- 预期：表单字段与后端契约无漂移（保存后读回一致）；test 接口按凭据真实性返回成功/失败
  文案；删除确认弹窗正常、误触可取消。

### 4.4 代码执行控制【P1】

- 步骤：打开 `/system-manage-extend/code-execution-control`；添加一个邮箱到授权名单；

- 预期：增删实时生效且 `cache_synced: true`（redis 同步）；授权用户代码执行走
  `FULL_CODE_EXECUTION_ENDPOINT`；删除后恢复受限。
