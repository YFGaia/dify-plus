## 3. 本次发现并已修复的问题

### 3.1 【阻断】SSR 预取 system-features 撞上 fork 健康检查 stub，登录后整个 Console 500

- 现象：任意账号登录后所有 commonLayout 路由 SSR 500（error boundary），无法自愈。
- 根因：fork 为 CVE-2025-63387 将 `/console/api/system-features` 改为 `{"ping":true}` stub（真实配置走 JWT 门禁的
  `/login_config`）。1.15.0 上游把 systemFeatures 预取搬进 SSR hydration boundary
  （`web/app/(commonLayout)/hydration-boundary.tsx`），client 侧已适配 login_config 但
  `web/features/system-features/server.ts` 漏改，stub 200 响应被当作合法数据 dehydrate，
  `main-nav` 读 `systemFeatures.branding.enabled` 时 TypeError。
- 止血修复（已提交）：`server.ts` 对响应做形状守卫（无 `branding` 视为不可用，回退 `defaultSystemFeatures`），
  客户端随后经 login_config 拿真实值。复验：登录后 6 条路由全部 200，payload 无 `{"ping":true}` 坏缓存。
- **后续提案素材**：更彻底的方案是 SSR 侧同样走 bootstrap JWT + login_config（需解决 SSR 并发下的 token 传递，
  bootstrap JWT 的 IP 校验对容器内请求的语义也需确认），并补"登录后首屏 SSR 200"的 e2e 断言。

### 3.2 compose 缺 `NEXT_PUBLIC_SOCKET_URL`，协作 websocket 连往 ws://localhost:5001

- fork compose 的 web 服务缺该变量，前端回退硬编码 `ws://localhost:5001`（nginx 后不可达）。
- 修复：`docker-compose.dify-plus.yaml` web 服务补 `NEXT_PUBLIC_SOCKET_URL: ${NEXT_PUBLIC_SOCKET_URL:-ws://localhost}`。

### 3.3 【高】WebApp 登录直扣链路断裂（计费链路 3）

- `api/controllers/web/completion.py` 的 `is_end_login` 调 `AccountService.load_logged_in_account(account_id=...)`
  缺上游 1.15.0 新增的必填 `session` 关键字参数；TypeError 被内部 except 吞掉，登录用户一律按未登录 401。
- 修复：补 `session=db.session`。复验：console cookie + passport 调 `/api/chat-messages` 200，
  扣费归因 admin（used_quota 增加、`end_user_account_joins_extend` 写入），api 日志无 `load_logged_in_account error`。

### 3.4 上游 1.15.0 的 `api_websocket` 服务未同步进 fork compose

- fork 的 nginx 模板与 `.env.example` 已引用 `api_websocket:5001`（`/socket.io/` 上游），但 compose 缺该服务定义，
  且 nginx 服务 environment 未透传 `NGINX_SOCKET_IO_UPSTREAM`（envsubst 置空会产生坏配置）。
- 修复：补 `api_websocket` 服务块（`collaboration` profile，fork 镜像），nginx 透传该变量并默认回落 `api:5001`。

### 3.5 Console 密钥限额接口（fork 扩展）PUT 500 / POST 额度字段为 null

- `api/controllers/console/apikey.py` 的 `_merge_token_with_quota_extend` 在 `db.session.commit()` 之后读 ORM
  `__dict__`：对象 expired 后 `__dict__` 为空 → `token_dict["id"]` KeyError → PUT 500（DB 已写入仅响应失败）；
  POST 创建响应未合并额度记录（字段全 null）。
- 修复：合并前先属性访问触发重载；`_create_api_key` 返回合并后的 `ApiKeyItem`。
  复验：POST 响应带额度字段、PUT 200 返回更新值、DELETE 204。apikey 单测 4 项、web 控制器单测 218 项全过。

### 3.6 本地构建 override 过期

- `docker-compose.local-build.yaml` 仍是 1.13.2 的子目录构建上下文与镜像 tag；已改为根上下文 + `1.15.0-local`，
  并补 `api_websocket` 镜像映射；`.env.local-test` 补 `COMPOSE_PROFILES` 与 socket 上游说明。

## 4. 记录在案的观察项（不阻塞，后续提案/运维注意）

### 4.1 extend_low 队列的"计划外重置任务执行"（计费回归时观察到）

- 现象：日/月重置任务在非计划时点密集执行（一轮约 30 次），beat 日志无对应派发记录，导致运行中的
  `day_used_quota`/`used_quota` 被计划外清零、日快照表灌入重复行。任务本身幂等，未损坏数据。
- 最可能解释：验证期间为腾内存多次 stop/start worker 容器 + 回归 agent 手动 `celery call`，
  未 ack 的队列消息在 worker 重启后被重投递；时间点与 worker 重启窗口吻合。member1 账号及其额度变动
  来自并行的 UI 回归 agent（邀请成员流程），非异常操作者。
- **提案素材**：给 3 个 extend 重置任务加执行窗口校验（仅零点/月初附近生效）或分布式锁 + 幂等键，
  避免生产上消息积压补跑造成额度误清零。

### 4.2 nginx 上游解析陈旧

- 容器重建后 api 换 IP，长时间运行的 nginx 曾以陈旧解析打旧 IP 返回 502（模板已有 `resolver ... valid=10s`，
  但实测未及时自愈），重启 nginx 恢复。生产升级 runbook 中建议在替换 api/web 容器后一并 `docker compose restart nginx`。

### 4.3 web 镜像构建内存要求

- `next build`（Turbopack）在 Docker VM 8GB（含运行中的全栈容器）下必现 `cannot allocate memory`（exit 129）。
  本地/CI 构建建议：VM ≥10GB 或构建时停掉 api 侧容器。

### 4.4 环境级前置（非代码问题）

- 本地 Docker 构建依赖宿主代理（Clash mixed-port 7890）在位：macOS 系统代理指向 127.0.0.1:7890 且
  Docker Desktop `ProxyHTTPMode=system`，代理进程掉线时容器内 80/443 全部失败（P3 时 9.1 被阻塞即此因）。
- `deb.nodesource.com` 无代理不可直达（api 镜像 production 阶段需要），构建前确认代理可用。
