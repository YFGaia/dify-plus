# Dify-Plus 1.17.1-plus.3 容器发布记录

本轮镜像固定源码为 `7baea00d32cc8c96b34a7b079829818981a912e5`，基于 Dify 社区版 `1.17.1`。API、Web、Agent 后端和 Agent 本地沙箱的 amd64 / arm64 原生构建、8 组冒烟及正式标签读回均已通过，[发布任务](https://github.com/YFGaia/dify-plus/actions/runs/39828043463)成功。不可变 index 和两平台子 manifest digest 见[镜像清单](./1.17.1-plus.3-images.json)。

2026-10-23 检查四组件匿名 token 请求均为 `401`。发布流水线已用授权账号核验镜像存在，部署方仍需使用有 GHCR 读取权限的账号登录。本轮没有更改 Package 可见性，也没有部署生产实例。

## 修复内容

- [#142](https://github.com/YFGaia/dify-plus/pull/142)：默认 Weaviate 从 `1.39.2` 升至 `1.39.13`，处理 Go 证书验证相关的 CVE-2026-111943。两架构实际二进制均使用 Go `1.26.10`；修复依据见 [Go 公告](https://github.com/golang/go/issues/82345)和 [Weaviate 发布说明](https://github.com/weaviate/weaviate/releases/tag/v1.39.13)。合并提交为 `708ee172cad9a3912269fa9a792353f8bd84639b`。
- [#134](https://github.com/YFGaia/dify-plus/pull/134)：仅升级 `weaviate-client`，从 `4.22.0` 至 `4.23.1`。原分组其余 13 项升级暂缓，现有服务端和调用接口仍需单独做兼容性迁移。没有升级 Qdrant、Chroma、Elasticsearch 或 Milvus。合并提交为 `bff19f5521212bb61c89066e34085f0695db6146`。
- [#138](https://github.com/YFGaia/dify-plus/issues/138)：登录前的配置令牌允许客户端 IP 变化。保留 HS256 验签、有效期、必需字段、令牌类型检查及一小时有效期；账号登录认证不受此令牌替代。修复提交为 `8aa884d26f821b9f505910dcf956f1a5364248fe`。
- 包含上次镜像发布后的 Casdoor SSO 显式角色映射恢复修复，以及钉钉扫码登录、诊断和显式账号绑定。真实企业身份提供方仍需使用部署方配置验收。

## 已完成的源码与向量库验证

- 登录配置、钉钉、Casdoor 定向后端回归：174 项通过；前端 5 个文件、150 项通过。目标 Weaviate SDK 定向单测另有 54 项通过。
- #142 与 #134 分别在原生 amd64、arm64 runner 上执行干净锁定安装；每次每架构 98 项单测和 1 项已有 SDK 集成通过，无失败或跳过。CI：[安全补丁](https://github.com/YFGaia/dify-plus/actions/runs/39825544323)、[SDK 更新](https://github.com/YFGaia/dify-plus/actions/runs/39826386294)。
- 每架构验证 8 个阶段：旧版基线、已有数据升级、写入、重启、新版目录恢复、旧版镜像与原始目录恢复、再恢复新版，以及 SDK 集成。镜像固定 digest；旧镜像只读取匹配的旧快照。

向量库演练使用单节点合成数据，恢复点为正常停机后的文件系统快照。它不覆盖生产数据、多节点集群或 Weaviate 逻辑备份模块。完整范围、源码和测试计数见[验证记录](./1.17.1-plus.3-verification.json)。

四组件镜像在各自原生平台实际启动或执行冒烟。API 两架构均装载 38 个 provider 元数据和 32 个向量入口，在临时 PostgreSQL 中完成两条迁移链，主链为 `c3f1a9b2e6d4`、扩展链为 `026_system_management_scope`，并通过 `/health` 和 `/console/api/system-features` 检查。该结果不代替旧生产库升级或真实外部服务验收。

## 部署前检查

1. 按[发布与部署指南](../容器镜像发布与多架构部署.md)核对四组件镜像来源、双架构及不可变 digest。API、WebSocket、worker、调度、初始化和迁移服务共用同一 API 镜像。
2. 保留数据库、文件、插件、向量库、配置与旧镜像的一致恢复点。已有 Weaviate 必须先用真实数据副本演练；旧 `1.19.0` 等版本不能直接跳到新默认版本读取原卷。不能用旧镜像读取已经升级的数据目录。
3. 本次与上次镜像源码相比没有新增数据库迁移文件。仍由单一执行者先运行 `flask db upgrade`，再运行 `flask extend_db upgrade`，业务副本保持自动迁移关闭。
4. 目标环境另验收企业登录、真实模型、知识库、插件、额度归因和工作流连接。镜像发布及组件启动检查不表示生产实例已升级。

本次记录对应容器版本；既有 GitHub 源码 Release `1.17.1-plus.1` 和历史容器 `1.17.1-plus.2` 保留原记录。
