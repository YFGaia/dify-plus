# 批量工作流数据表冷备归档说明

> 状态：功能已删除（2026-07-05，决策点 D2 定案为方案 A），数据表冷备保留
> 决策依据：`openspec/changes/p1-batch-workflow-disposition/proposal.md`（决策结论小节）
> 上位文档：[实现线路图-upstream-1.15.0升级与admin废弃](./实现线路图-upstream-1.15.0升级与admin废弃.md) 决策点 D2

## 涉及数据表

| 表名 | 建表来源 | 用途 |
|---|---|---|
| `batch_workflows_extend` | Go admin-server（GVA）GORM AutoMigrate，模型定义 `admin/server/model/gaia/batch_workflow.go` | 批量工作流批次记录：上传的 Excel 文件名、总行数/已处理行数、状态（pending/processing/completed/failed/stopped）、结果汇总、错误信息 |
| `batch_workflow_tasks_extend` | 同上 | 批次内逐行任务记录：行索引、输入参数、单任务状态（pending/running/completed/failed/cancelled）、结果与错误 |

两张表**不在** fork 的 Alembic 迁移链（`api/migrations_extend`）内，由 GORM 在 admin-server 启动时自动建表。`batch_workflows_extend.user_id` 是 GVA `sys_users` 表的 uint 主键（非 Dify `accounts` uuid）。

## 历史用途

批量工作流允许用户在 WebApp 运行页（text-generation 界面）上传 Excel，由 admin-server（Go）后台逐行调用 workflow/completion 应用并汇总结果下载。前端通过 `web/service/web-extend.ts` 直调 `/admin/gaia/workflow/batch/*` 8 个端点。

## 删除范围（方案 A，已执行）

- 前端：`web/service/web-extend.ts`、`web/utils/batch-progress-manager.ts`、`run-batch/batch-progress/` 组件、`text-generation/index.tsx` 及 `run-batch/` 的 fork 批量改造（恢复上游原生实现）、各语言 `extend.json` 的 `batchWorkflow.*` i18n key。
  - 随 fork 批量一并引入的 `csv-reader` CSV GBK 编码探测定制（jschardet + papaparse 自定义 reader）也随之移除，恢复上游 `react-papaparse` 实现。
- Go 侧实现（`admin/server/service/gaia/batch_workflow.go` 691 行、`worker_pool.go` 1,274 行、`admin/server/api/v1/gaia/workflow.go` 669 行）**未在本次删除**，随 P5（`p5-admin-decommission`）统一清理。
- 报表脚本 `api/services/batch_workflow_statistics_service.py`（依赖 `sys_users` join）随 P5 一并删除。

## 保留原因

- 历史批次与任务数据可能有审计/追溯价值，删除功能 ≠ 删除数据。
- 方案 A 的回滚路径依赖数据表完整：若误判使用量，可按方案 B 路径恢复功能且历史数据无损。
- **确认无 DROP/TRUNCATE 发生**：本 change 未执行任何数据库变更。

## 能否删除这两张表？

可以，但建议在 P5（admin 废弃）完成、且确认无审计需求后，再单独安排不可逆清理窗口执行 DROP。在此之前保持冷备。

## 恢复路径（若未来需要恢复功能）

按 `openspec/changes/p1-batch-workflow-disposition/design.md` 的**方案 B** 设计实施：

1. 数据主权移交：在 `api/migrations_extend` 用存在性检查幂等声明两张表，新增 `account_id` uuid 列，`user_id` 经 `sys_users → accounts` 映射回填（design.md D-4）。
2. 执行链路：Celery 低优先队列 + 进程内调用 `AppGenerateService.generate()`，以批次创建者 account 计费归因，杜绝伪造 JWT（design.md D-3）。
3. API 面：Console API 8 端点语义兼容原 Go 实现（design.md D-5），前端按 contract-first（`web/contract/console/` + TanStack Query）重写。
4. 前端组件可从 git 历史找回：本 change 删除前的最后版本见 tag/分支 `merge/upstream-1.13.3` 上的提交历史（`web/service/web-extend.ts` 等）。
