## 0. 环境与命令口径

- `pnpm install`：三次确认（根目录），lockfile 与 node_modules 一致，无上游版本漂移。
- **环境修复 1**：`packages/dify-ui` 与 `packages/jotai-tanstack-form` 的 node_modules 符号链接过期
  （缺 `storybook`、`vitest` 链接，导致 12 个 `typescript(TS2307)` 假错误）。删除两包 node_modules
  后重跑 `pnpm install` 恢复。**非代码问题，不计入修复清单**。
- **环境坑 2**：直接 `pnpm exec vp check <path>` 报 `Cannot find binary path for command 'node'`
  （pnpm exec 注入的 PATH 含相对路径条目，vp 解析不了）。绕过方式：
  `PATH="$PWD/node_modules/.bin:$PATH" ./node_modules/.bin/vp <cmd>`。根目录 `pnpm check`
  等 run-script 形式不受影响。
- 1.16.0 起 lint 体系为 Vite+（`vp check` = Oxfmt + Oxlint + tsgo 类型检查）+ ESLint（仅非代码文件），
  基线抑制文件为根 `oxlint-suppressions.json` / `eslint-suppressions.json`（web/docs/lint.md）。
  fork 的 1.15.0 基线**没有**这套体系，因此 fork 存量代码首次被新 lint 覆盖，所有违规都在本阶段处理。

### 3.4 chat utils 快照失败的根因认定（上游既有，非 fork）

- 该 spec、快照文件、`vitest.setup.ts`、`web/vite.config.ts`、根 `vite.config.ts`、`web/test/`
  **全部与上游 1.16.0 逐字节一致**（git diff 为空）。
- 单独跑该 spec：**47/47 全绿**（含 `--silent=passed-only` 同参数复验）；跑整个
  `app/components/base/chat` 目录：一次 1 失败、复跑两次全绿——**负载相关的非确定性失败**。
- 根因：`node_modules/.pnpm` 中存在 **4 个 vitest@4.1.10 实例**（`@types/node@25.9.5` 三种
  peer 组合 + `@types/node@26.0.1` 一种），多实例导致 SnapshotClient 状态不共享——与
  vitest-dev/vitest #7668/#8622（"ensure snapshot client is singleton"）完全吻合。
- 双 `@types/node` 变体是**上游 1.16.0 lockfile 自带**（上游 tag 内 25.9.5 引用 179 处、
  26.0.1 引用 102 处），非 fork 合并引入。
- 该 spec 是 web 项目**唯一**使用文件快照（`__snapshots__/*.snap`）的用例，故全仓只有它受影响；
  CI 4-shard 拆分下未见暴露。
- 处置：不动 lockfile 去重（会整体偏离上游 lockfile，合并期风险大于收益）；登记遗留，
  待上游升级 vitest（含 #8622 修复）或统一 `@types/node` 后自愈。
