# 升级到 1.15.0 说明（自 1.12.1 或更早版本）

本文面向从 Dify-Plus `1.12.1`（`main` 分支 / 最后一个公开 release）升级到 `1.15.0` 的部署方。
上游跨度为 Dify 1.12.1 → 1.15.0（中间经 1.13.2 / 1.13.3 / 1.14.2 逐级合并）；
fork 侧最大的变更是 **GVA（gin-vue-admin）管理后台整体下线**。

> 通用的上游升级流程与回归范围见[上游升级与回归检查清单](./上游升级与回归检查清单.md)；
> 本文是一次性的版本专项说明，两者配合使用。
> 实际演练记录（1.13.2 旧库 → 1.15.0，含踩坑）见[1.15.0 升级本地容器验证记录](./1.15.0升级本地容器验证记录.md)。

## 1. 重大变更一览

### 1.1 GVA 管理后台移除（破坏性）

- `admin/` 目录、`admin-web` / `admin-server` 两个容器服务、`docker/admin-server/` 配置全部删除
  （删除前代码留档于 tag `pre-admin-removal`）。
- 管理能力并入 Console 顶部导航「系统管理」（仅 workspace owner 可见）：
  - 系统集成（钉钉 SSO / OAuth2 / 邮箱 API / 转发 Token）：`/system-manage-extend/system-integration`
  - 用户额度管理：`/system-manage-extend/quota-management`
  - 代码执行控制（sandbox-full 授权名单）：`/system-manage-extend/code-execution-control`
- 以下 GVA 功能**无 Console 对应项，直接移除**（升级前请确认无依赖）：
  Dashboard 费用报表与密钥使用分析、租户目录、模型供应商网关、转发代理（`/gaia/forward/proxy/*`）、
  应用版本管理、后台创建用户、批量工作流处理（D2 决策删除，数据表冷备说明见
  [批量工作流数据表冷备归档说明](./批量工作流数据表冷备归档说明.md)）。
- GVA 框架数据表（`sys_*`）由扩展迁移 `016_drop_gva_admin_tables` 清理，**DROP 前必须 pg_dump 备份**。

### 1.2 上游 1.13.x / 1.14.x / 1.15.0 关键行为变化

- **SSRF 代理默认拒绝私有网段**（1.15.0）：工作流 HTTP 节点、自建工具访问内网必须配置白名单
  `SSRF_PROXY_ALLOW_PRIVATE_IPS` / `SSRF_PROXY_ALLOW_PRIVATE_DOMAINS`，漏配表现为内网请求批量 403。
- **工作流协作 websocket**（1.15.0）：新增 `api_websocket` 服务（`collaboration` compose profile），
  浏览器经 nginx `/socket.io/` 路由接入，涉及变量 `COMPOSE_PROFILES`、`NEXT_PUBLIC_SOCKET_URL`、
  `NGINX_SOCKET_IO_UPSTREAM`。
- **租户插件自动升级策略**需要执行回填命令（见下文第 3 步），跳过则该设置静默失效。
- 应用中心分类从 fork 自建分类表迁入上游原生 `recommended_apps.categories`（扩展迁移 017/018）。

## 2. 升级前准备（强制）

1. `pg_dump` 整库快照 + 生产 `.env` 备份。跨版本 `flask db downgrade` 不可靠，快照是唯一可靠的 DB 回滚手段。
2. 停止全部服务：api / worker / worker_beat / web，以及旧的 **admin-web / admin-server**。
3. 收集内网访问目标清单（HTTP 节点、内部工具、自建 API），用于第 4 步 SSRF 白名单。

## 3. 数据库迁移序列（顺序不可调换）

更新代码 / 镜像到 `1.15.0` 后，在 api 容器（或源码环境）内依次执行：

```bash
# 1) 上游迁移链（1.12.1 → 1.15.0 全部上游迁移）
flask db upgrade

# 2) fork 扩展链，分段执行以保留退路：
#    2a. 建代码执行控制新表
flask extend_db upgrade --revision 015_code_execution_control

#    2b. 把 GVA 代码执行授权名单迁入新表并重建 redis 缓存（幂等可重跑；
#        GVA 源表不存在时自动跳过，不报错）
flask extend_db migrate-code-execution-control

#    2c. 016 DROP GVA sys_* 表（已在第 2 步备份）→ 017 应用中心分类数据迁入原生表
flask extend_db upgrade --revision 017_migrate_recommended_cats

# 3) 回填租户插件自动升级策略【强制】
flask backfill-plugin-auto-upgrade
```

执行后抽验：

- `SELECT count(*) FROM tenant_plugin_auto_upgrade_strategies;` 非零；
- 分类迁移一致性 SQL 见[检查清单第 0 节](./上游升级与回归检查清单.md)第 4 条（018 执行前有效）。

**018（删除两张 fork 分类表）留到回归之后**：待应用中心 / 探索页回归通过，再执行
`flask extend_db upgrade` 升到扩展链 head。回归前不执行 018，代码回退即可回到旧分类路径。

## 4. 环境变量与部署拓扑对齐

以 1.15.0 的 [`docker/.env.example`](../../docker/.env.example) 为准逐项比对生产 `.env`，重点：

| 变量 | 说明 |
| --- | --- |
| `SSRF_PROXY_ALLOW_PRIVATE_IPS` | 逗号分隔，支持 CIDR，如 `10.1.2.0/24,192.168.1.10`【最易漏】 |
| `SSRF_PROXY_ALLOW_PRIVATE_DOMAINS` | 逗号分隔，支持通配，如 `.internal.example.com` |
| `COMPOSE_PROFILES` | 需包含 `collaboration` 才会启动 `api_websocket` 服务 |
| `NEXT_PUBLIC_SOCKET_URL` | 暴露给浏览器的协作 websocket 地址（默认 `ws://localhost`，经 nginx 路由）；缺失时前端回退 `ws://localhost:5001` 不可达 |
| `NGINX_SOCKET_IO_UPSTREAM` | nginx `/socket.io/` 上游，默认 `api_websocket:5001` |

拓扑变更：

- **删除** `admin-web`、`admin-server` 服务及其反代路由、防火墙放行、监控探活等配套；
  移除 admin 专用配置（如 `ADMIN_GROUP_ID`）。
- **新增** `api_websocket` 服务（同 api 镜像，`collaboration` profile）。
- **SECRET_KEY 轮换（强烈建议）**：GVA 后台曾与 api 共享 `SECRET_KEY`，admin 下线后按
  [SECRET_KEY 轮换 runbook](./SECRET_KEY轮换runbook.md) 在维护窗口轮换，消除历史共享密钥风险。

## 5. 启动与回归

```bash
cd docker
docker compose -f docker-compose.dify-plus.yaml up -d
```

最小回归范围（详见[检查清单](./上游升级与回归检查清单.md)第 9 节与[计费回归基线清单](./计费回归基线清单.md)）：

1. Console 登录，默认落点为应用中心；顶部额度徽章正常。
2. 钉钉 / OAuth2 登录。
3. 「系统管理」入口（owner 账号）与 3 条子页面可用；普通成员不可见。
4. API 密钥创建 / 日月限额编辑 / 限额 403 拦截。
5. 发一轮消息确认扣费；WebApp 登录直扣归因正常。
6. 应用中心分类展示与过滤（通过后执行 018）。
7. SSRF 白名单双向：加白内网目标可访问，未加白私有目标仍 403。
8. 工作流协作 websocket：浏览器 `/socket.io/` 经 nginx 可连通。

## 6. 回滚路径

- 代码：回退到升级前 tag（GVA 时代代码在 `pre-admin-removal`；1.12.1 发行版为 `1.12.1`）。
- 数据库：用第 2 步 pg_dump 快照整库恢复（016 已 DROP GVA 表、上游迁移已跨版本，逐级 downgrade 不可靠）。
- 若尚未执行 018，fork 分类表数据天然保留，仅回退代码即可回到旧分类路径。

## 7. 运维注意事项（来自本地验证实测）

- 替换 api / web 容器后建议一并 `docker compose restart nginx`：nginx 上游 DNS 解析可能陈旧导致 502。
- web 镜像构建（`next build`）内存要求高：Docker VM 建议 ≥10GB，或构建时停掉其他容器。
- 额度日/月重置任务在 worker 频繁重启 + 队列消息积压时可能被补跑（任务幂等，但会出现计划外清零），
  生产升级窗口内避免反复重启 worker；详见[验证记录 §4.1](./1.15.0升级本地容器验证记录.md)。
