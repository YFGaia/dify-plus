为排除「主链泄漏建表」的可能做了两组对照复验：

结论：双链行为确定性正确，首轮日志缺行为一次性采集异常，未再复现，不影响结论。

## 4. 一次性命令 runbook 结论（全新库实测 + 代码考证）

| 命令 | 全新库行为（实测） | runbook 结论 |
| --- | --- | --- |
| `flask rbac-migrate-dataset-permissions`（默认 dry-run） | 正常执行，"No datasets found for migration." | **不进标准升级序列**。RBAC 由企业版配置 `RBAC_ENABLED` 门禁（默认 false，fork 自托管不启用，`login_config` 实测 `rbac_enabled: false`）；仅当部署显式开启企业 RBAC 时才需要迁移存量知识库权限，且命令默认 dry-run、需 `--apply` 才写入，届时先 dry-run 观察再执行 |
| `flask rbac-migrate-member-roles --dry-run` | 正常执行，"No workspace members found for migration." | 同上（成员角色迁 RBAC，与 fork 无交集，不进序列） |
| `flask backfill-workflow-run-archive-bundles --dry-run` | 报 `ArchiveStorageNotConfiguredError`（要求 `ARCHIVE_STORAGE_ARCHIVE_BUCKET`） | **不进标准升级序列**。用途是从对象存储归档 manifest 反向重建 `workflow_run_archive_bundles` 索引表；归档功能是 1.16.0 新增，fork 各环境从未产生过归档 manifest，无可回填之物。仅当未来启用 workflow-run 归档且需要引导/修复索引时按需执行 |
| `flask backfill-plugin-auto-upgrade` | 正常执行，"Found 0 candidate tenants"，幂等完成 | **1.15.0 已升级过的环境无需重跑**（1.15.0 runbook 已含）；从 1.14.x 及更早直跳 1.16.0 的环境仍按三段链保留为第三步。重复执行无害（幂等） |

即 1.15.0 → 1.16.0 的升级命令链就是两段：`flask db upgrade` → `flask extend_db upgrade`，无新增一次性命令。

### 5.3 setup / 登录（含上游 1.16.0 行为变化，重要）

- `GET /setup` → `not_started`；`POST /setup` → 201 创建管理员。
- **上游行为变化 1**：`POST /console/api/login` 的 `password` 字段必须 **Base64 编码**
  （1.16.0 新增 `@decrypt_password_field`，明文直传报 401 "Invalid encrypted data"）。
- **上游行为变化 2**：登录态改为 **Cookie 会话**（HttpOnly `access_token`/`refresh_token` + 非 HttpOnly `csrf_token`），

  仅带 Cookie 会 401。
- 影响面：任何直调 console 登录 API 的 fork 脚本/巡检/自动化工具需按上述两点适配（已列入 §8 遗留项）。
