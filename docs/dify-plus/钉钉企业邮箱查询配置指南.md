# 钉钉扫码接入、登录与企业邮箱配置指南

入口：系统管理 → 系统集成 → 钉钉。仅实例初始化空间中真实角色为 owner/admin 的账号可管理配置。

## 两种独立接入方式

- **扫码创建或授权应用**：无需预先填写 AppKey / AppSecret。页面向钉钉申请注册二维码，企业管理员扫码确认后，后端接收并加密保存返回的应用凭证。二维码会过期，可取消或重新生成。
- **手动填写应用凭证**：已有应用可直接填写 AppKey / AppSecret 并保存。已保存的 Secret 不回显，留空表示保留原值。

两条路径取得凭证后，均需完成真实登录诊断，再启用登录入口。扫码注册协议主要面向应用创建；取得凭证本身不代表钉钉已配置好登录权限或回调地址。请在钉钉开发者后台为对应应用配置页面展示的回调地址，并按实际诊断结果开通用户个人信息及企业通讯录读取权限。生产回调要求 HTTPS；本地开发模式允许 localhost / 127.0.0.1 HTTP。

## 验证与启用

1. 选择扫码接入或手动配置，取得并保存应用凭证。
2. 打开钉钉开发者后台中的对应应用，在「安全设置 → 重定向 URL（回调域名）」保存 Dify 页面展示的完整 OAuth 回调地址。
3. 在「权限管理」开通 `Contact.User.Read`（通讯录个人信息读权限）和 `qyapi_get_member`（成员信息读权限）。后者用于根据 unionid 查询用户及查询用户详情；确保待登录成员处于应用可用范围。根据钉钉后台要求发布配置。
4. 执行连接测试，确认应用凭证可换取钉钉应用令牌。
5. 执行真实登录诊断，在钉钉扫码授权；后端验证用户身份、企业成员关系和当前配置版本。如果管理员要使用钉钉登录当前已有的 Dify 账号，应先勾选「将本次验证的钉钉身份绑定到当前本地账号」，该选项默认不勾选。绑定目标为发起验证时已登录的本地账号，后续扫码沿用该账号已有的空间角色。诊断不会切换当前登录账号，也不会代其他成员绑定账号。
6. 诊断通过后启用。普通登录页显示钉钉入口，用户点击后进入钉钉扫码登录；已有钉钉会话时，官方页面可能显示「立即登录」。

如果已取得凭证、连接测试通过，但「启用」不可用，查看「真实登录验证」状态并完成上述配置。连接测试仅验证应用凭证，不验证用户登录、回调或成员权限。若钉钉授权页提示「应用不存在」，先核对当前应用 Client ID 与回调配置；缺少回调配置可能导致该提示。尚未绑定且没有有效企业邮箱的用户不能创建新账号，应由管理员配置真实企业邮箱查询后再试。已有同邮箱账号不会因此自动绑定。

配置变更或停用会使未完成的授权与验证结果失效，需要重新验证。停用后不再允许发起或完成新的钉钉登录；已经签发的 Dify 会话按现有会话规则处理。

## 企业邮箱查询

企业邮箱查询可根据钉钉用户 ID 从企业通讯录或员工接口获取真实邮箱，用于新账号注册。它不负责发送验证码、邀请或重置密码邮件；邮件发送仍由部署的 MAIL_TYPE 及对应 SMTP、Resend、SendGrid 配置控制。

## 常见配置

以企业接口 `GET https://directory.example.com/users/email?userId=员工钉钉ID` 返回下面结构为例：

```json
{"data": [{"userName": "employee@example.com"}]}
```

1. 打开企业邮箱查询开关。
2. API 地址填 `https://directory.example.com/users/email`，请求方式选 GET。
3. 用户 ID 参数名填 `userId`。无需在地址中手动拼接这个参数，系统会填入当前登录用户的钉钉 ID。
4. 返回邮箱字段填 `data[0].userName`。返回 `{"data":{"email":"employee@example.com"}}` 时改填 `data.email`；顶层 email 字段填 `email`。
5. 如果接口要求 `Authorization: Bearer ...`，选择 Bearer 并输入 Token；HTTP Basic 选择 Basic 并填写用户名、密码；其他鉴权可在高级请求头 JSON 中配置。
6. 输入一个真实的钉钉用户 ID，点击测试邮箱查询，确认展示的是该员工的正确邮箱。
7. 点击钉钉配置的保存按钮。测试使用当前草稿，不会保存配置，也不会创建账号。

接口必须返回 HTTP 200 和可提取的邮箱字符串。API 地址应能从 Dify 后端访问，并符合部署的 SSRF 代理策略；测试失败时检查地址、鉴权、用户 ID 和返回字段路径。

## POST 及高级配置

请求方式为 POST 时，默认将用户 ID 作为 JSON 字段发送。高级请求体配置沿用既有结构：

```json
{"raw": "{\"tenant\":\"example\"}"}
```

上述配置和默认参数名会发送：

```json
{"tenant":"example","userId":"当前钉钉用户ID"}
```

选择表单请求体时分别使用 `form_data` 或 `urlencoded`：

```json
{"urlencoded": [{"key": "tenant", "value": "example"}]}
```

请求头使用 JSON 对象，如 `{"X-Directory":"enterprise"}`。用户 ID 参数始终由系统填入，覆盖请求体中同名字段。后端配置支持 PUT/DELETE、Basic 鉴权、请求头、表单请求体等参数；使用前核对界面可选项与接口支持。

## 登录行为与生效范围

登录以应用及企业范围内的钉钉稳定身份绑定 Dify 账号，不按姓名拼音生成邮箱，也不凭相同邮箱自动接管已有账号。已有账号需要显式绑定；新账号必须取得有效的真实企业邮箱，并作为普通成员加入实例初始化空间。已停用账号或已移除成员不会通过扫码自动恢复权限。

钉钉企业管理员身份不直接授予 Dify 管理权限。登录后的空间角色由本地成员关系决定；全局系统管理还要求当前空间为实例初始化空间、真实成员角色为 `owner` 或 `admin`。另一位员工首次扫码不会共享已绑定的管理员账号。

开启企业查询时，接口失败会阻止登录，避免把错误身份继续映射到其他账号。未开启时使用钉钉企业成员资料中的企业邮箱或邮箱。已完成身份绑定的账号可无需邮箱登录。

配置保存在钉钉 `config.email_api`，鉴权及请求配置加密保存、读取时脱敏。普通邮箱登录、OAuth2、Casdoor 登录不使用这项配置。不要在聊天、截图或仓库中保存应用 Secret、Token 或真实人员信息。
