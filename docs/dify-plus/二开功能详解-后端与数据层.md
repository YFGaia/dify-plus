# Dify-Plus 后端与数据层功能

本文介绍当前源码提供的二开能力及其边界。产品入口见[项目 README](../../README.md)，配置与部署见[部署说明](./二开部署配置与运维说明.md)，表结构与迁移见[数据库说明](./二开数据库与迁移说明.md)。

## 系统管理权限

实例级配置共用 `SystemManagementAccessService`：当前账号必须处于实例初始化空间，在数据库中的真实角色为 `owner` 或 `admin`，账号和空间均有效。初始化空间保存于 `system_management_scope_extend`，由安装流程写入或扩展迁移依据安装记录核验回填。

普通成员、其他空间的 owner/admin 均不能访问系统管理 API。切换空间后重新检查权限；初始化空间失效时拒绝访问，不自动选择替代空间。空间名称、固定 UUID、Casdoor 默认登录空间、RBAC 开关及 `CASDOOR_CONFIG_ADMIN_ACCOUNT_IDS` 均不授予实例管理权限。

主要入口：

- `api/services/system_management_access_service_extend.py`
- `api/models/system_management_scope_extend.py`
- `api/controllers/console/system_management_permissions_extend.py`

## Casdoor SSO

Casdoor 通过独立的原生 Console 集成提供单点登录，与通用 OAuth2 配置分开维护。

管理员配置 Casdoor 浏览器访问地址、后端 API 地址、Issuer、组织、应用、Client ID、Client Secret 和默认登录空间。支持保存草稿、静态检查、真实登录诊断、激活与禁用；草稿不直接影响用户登录。配置使用不可变版本和 ETag 检查，诊断必须对应当前版本。Secret 加密保存，读取响应仅显示存在状态。

登录时跳转至 Casdoor，回调换取令牌并自动获取、缓存和刷新签名公钥，完成签名及身份声明校验后签发 Dify 本地 access/refresh/CSRF 会话。

SSO 的空间角色使用精确的“组织 + 角色名称”映射到 `admin`、`editor`、`normal`，默认空间保留普通成员兜底。映射不授予 `owner`，也不绕过初始化空间系统管理权限。

同一身份绑定的托管成员此前被 Dify 移除后，当前显式角色映射可在登录事务中恢复成员及角色，保留原托管基线并记录恢复审计；默认普通成员兜底不触发恢复。现存人工角色覆盖、owner、已释放关系和其他身份命名空间的历史不被自动接管，权限任务仍受登录屏障检查。

主要入口：`api/controllers/console/casdoor_config_extend.py`、`api/controllers/console/auth/casdoor_extend.py`、`api/core/casdoor/configuration.py`、`api/services/casdoor_signing_key_service_extend.py`。

## 钉钉与通用 OAuth2

系统管理提供钉钉配置、连接测试、登录回调测试和企业邮箱查询接口测试。钉钉登录服务负责换取令牌、获取身份、查询企业邮箱并映射账号；邮箱查询详见[钉钉指南](./钉钉企业邮箱查询配置指南.md)。

通用 OAuth2 提供服务地址、授权/令牌/用户资料配置与连接测试，由原生 OAuth 控制器处理回调。它与 Casdoor 原生集成是独立入口。

`/system-features` 仅公开启动所需的最小字段；二开登录字段通过独立登录配置接口提供，不应把私有配置加入公共系统特性响应。`system_integration_extend` 保存钉钉及通用 OAuth2 配置；表中的微信、飞书分类枚举不代表当前有对应的完整产品入口。

## 个人额度与 API Key

个人 `total_quota` 表示总额度，`used_quota` 表示已用额度，余额为二者之差。二开费用按 USD 归一，非 USD 费用使用 `RMB_TO_USD_RATE` 换算。它独立于上游 Cloud 套餐及供应商 quota。

账号创建通过 `ensure_account_quota_extend()` 初始化额度；管理员可按姓名/邮箱搜索、按消费排序并设置总额度。修改总额度保留已有消费，不等同于充值流水或退款操作。

聊天消息费用由消息事件记录；工作流 LLM 节点费用由 `extend_high` 队列任务写入。API 请求通过消息/运行与 Key 的关联更新密钥消费。

| API Key 字段 | 含义 |
|---|---|
| `day_limit_quota` / `month_limit_quota` | 日/月限额；`-1` 表示该周期不限额 |
| `day_used_quota` / `month_used_quota` | 当前日/月已用额度 |
| `accumulated_quota` | 累计已用额度，不是生命周期总额度上限 |

入口在已达到个人或 Key 周期限额时拒绝后续调用；实际费用在消息或节点执行后记录。不能将入口校验描述为预扣款，或承诺并发请求绝不超过额度。

启用 `ENABLE_EXTEND_QUOTA_RESET_TASKS` 后，Celery Beat 每天零点快照并清零 Key 日消费，每月 1 日零点快照并清零个人/月度 Key 消费；时间基于实际 Celery 配置时区。任务运行于 `extend_low`，需要 Beat 与消费该队列的 worker。

## WebApp、上下文与应用中心

`AppExtend.webapp_auth_enabled` 控制每个公开 WebApp 的登录要求。未配置、NULL 或 True 均要求 Console 登录；False 允许匿名生成。授权重新读取数据库，Redis 只是投影缓存。匿名请求无 Console 账号时不计入个人账号费用；已登录用户仍进行账号归因。

`workflow_run_account_extend` 保存首次运行时的空间、应用与 Console 操作账号，匿名运行明确保存 NULL。恢复运行不能将归属改成恢复者；历史缺失归因保持未知。日志查询沿空间、应用、运行与账号边界执行。

`AppExtend.retention_number` 保存上下文轮数，运行时写入 `message_context_extend` 分段位置；读取记忆时按分段边界处理。`/message/context` 验证会话所属空间及应用权限后提供查询和删除能力。清理分段标记不等同于删除聊天内容。

应用中心复用 Dify 推荐与已安装应用体系，支持同步到模板中心、安装/卸载、置顶与排序；`app_statistics_extend` 保存使用次数，分类使用原生 `recommended_apps.categories`。

主要入口：`api/services/webapp_auth_service_extend.py`、`api/services/workflow_run_account_extend.py`、`api/controllers/console/app/app_extend.py`、`api/services/recommended_app_service_extend.py`。

## 代码节点执行授权

系统管理维护 `code_execution_control_extend` 邮箱名单，每次写入后重建 Redis `control_mail` 投影。执行时以空间 owner 邮箱是否命中名单决定代码节点是否送往 `FULL_CODE_EXECUTION_ENDPOINT`。

未命中名单、缓存缺失、格式错误或读取失败时使用普通 sandbox。名单授予空间执行环境能力，并非登录用户的系统管理权限；完整环境还需部署对应服务。

## 工作流冷备与恢复

运维命令通过 S3 兼容存储把已结束的运行按空间/月/分片写入 V2 bundle，包含 Parquet 与 manifest。归档覆盖运行、应用日志、节点执行、卸载数据、暂停及触发日志；归档本身保留源数据库记录。

- `archive-workflow-runs-plan`：估算固定时间窗口内的范围。
- `archive-workflow-runs`：写入归档对象及索引，支持预览。
- `backfill-workflow-run-archive-bundles`：从 manifest 回填索引。
- `restore-workflow-runs`：校验内容后恢复源记录。
- `delete-archived-workflow-runs`：单独执行校验和删除。

Console 包含按月归档列表、下载任务与 ZIP 下载 API，但控制器限定 **Cloud 部署与付费套餐**，不能承诺所有自托管实例都能访问。自托管运维以 CLI 和实际存储配置为准。

旧批量工作流业务表的冷备留存见[历史数据说明](./批量工作流数据表冷备归档说明.md)，与运行日志归档的数据范围不同。

## 维护边界

控制器负责请求解析，服务负责编排，`core/casdoor` 负责策略，repository 负责事务与持久化。配置从 `configs.dify_config` 读取，异步工作使用现有 Celery 队列。

`tenant_model_sync_extend`、`model_sync_config_extend` 与旧模型同步服务仍存在，但没有存活调用方，旧服务依赖的供应商方法已不存在；它们是保留结构，不能作为当前跨空间模型同步功能。模型配置使用 Dify 原生供应商管理。

遗留转发路由与计费结构不构成完整管理产品；有道 OCR helper 没有注册的独立图片翻译接口。应从真实路由与调用关系确认能力，不能凭表或函数存在推断可用。

数据库有两条独立版本链。认证、费用、邀请、异步任务与存储结果需要分别核实；页面成功、API 成功或对象存在不能替代最终业务数据回读。
