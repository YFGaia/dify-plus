# Dify-Plus 与上游能力对照

本文按当前仓库基于 Dify 1.17.1 的实现说明 fork 能力与维护边界，供选型、开发定位和回归使用。应用、工作流、知识库、模型、插件、Agent v2 与工作流协作是 Dify 主体能力；下表说明 Dify-Plus 在其上的业务扩展。

## 核心功能

| 功能域 | Dify-Plus 最终能力 | 入口与关键实现 |
| --- | --- | --- |
| 应用中心与模板分发 | 展示当前空间已发布的安装应用，支持模板 / 推荐应用同步；首次使用前无统计记录的应用同样可见 | `/explore/apps-center-extend`；`recommended_app_service_extend.py`、`controllers/console/app/app_extend.py` |
| 个人余额 | 个人余额、已用额度、月度使用统计及使用者信息；系统管理员设置总额度，保留已有消耗 | `AccountMoneyExtend`、`AccountMoneyMonthlyStatExtend`；导航余额与应用用户总览 |
| API 密钥限额 | 应用密钥日 / 月限额、日 / 月消耗和累计使用量；调用前校验，消费归因到实际密钥 | `controllers/console/apikey.py`、`controllers/service_api/wraps.py`、`ApiTokenMoneyExtend` |
| 消息与工作流计费 | 消息和成功工作流节点按 usage 计费，支持 Console、已认证 WebApp、Service API 的账号 / Run / 密钥归因 | 消息事件处理器、`tasks/extend/update_account_money_when_workflow_node_execution_created_extend.py`、`workflow_run_account_extend.py` |
| 周期额度管理 | 个人月度额度、密钥日 / 月使用量的周期重置和统计 | `schedule/*extend.py`、`extensions/ext_celery.py`；扩展重置调度开关 |
| 会话记忆 | 应用级记忆保留窗口、消息上下文选择与使用控制 | `token_buffer_memory.py`、`AppRunner.add_messages_context`、`retention-number-extend`、chat 组件 |
| WebApp 访问认证 | 每应用访问认证开关；默认使用 Console 登录与空间权限，关闭后允许匿名访问 | `webapp_auth_service_extend.py`、`webapp_console_identity_extend.py`、标准 `controllers/web/passport.py` |
| 原生系统管理 | Console 统一管理集成、用户余额及代码执行名单；已去除 GVA 独立后台 | `/system-manage-extend/*`；`system_manage_extend.py`、`system_management_access_service_extend.py` |
| 初始化空间管理权限 | 实例初始化空间中真实 owner / admin 才能配置系统；菜单、页面与 API 使用同一权限边界 | `SystemManagementScopeExtend`、`SystemManagementAccessService`、系统管理权限 API |
| Casdoor SSO | 配置草稿、静态校验、真实登录诊断和激活；自动发现签名公钥、登录验签及加密 Secret | `controllers/console/auth/casdoor_extend.py`、`casdoor_config_extend.py`、`services/casdoor_*_extend.py`、`core/casdoor/` |
| 钉钉与 OAuth2 | 钉钉登录、企业邮箱查询、OAuth2 登录参数配置与连接测试 | `ding_talk_extend.py`、`dingtalk_email_lookup_extend.py`、`libs/oauth.py`、系统集成页面 |
| 完整代码执行控制 | 管理允许使用完整沙箱的邮箱名单，按授权选择扩展执行环境 | `CodeExecutionControlExtend`、`CodeExecutionControlService`、`sandbox-full` |

### 额度语义

- 个人 `total_quota` / `used_quota` 是 fork 余额，与模型提供商配额独立。金额根据 usage 的货币及部署汇率换算。
- 密钥 `day_limit_quota` / `month_limit_quota` 是限制；`day_used_quota` / `month_used_quota` 是周期用量；`accumulated_quota` 是累计用量，不能当作终身额度上限。
- 工作流计费依赖 `extend_high` 消费者，必须核对任务消费及数据库读回；HTTP 成功、零 token 的工作流结果不能证明真实扣费完成。

### 权限与身份语义

系统管理固定在数据库记录的初始化空间，真实角色要求 owner / admin。其他空间的管理员、旧 `CASDOOR_CONFIG_ADMIN_ACCOUNT_IDS`、RBAC 开关及 Casdoor 默认登录目标均不授予实例管理权限。切换空间后重新校验。

Casdoor SSO 当前支持 Community / RBAC 关闭的配置，激活需要精确配置 revision 的静态校验和真实诊断。登录使用自动发现的签名公钥验签，Client Secret 加密保存。Enterprise / RBAC 开启模式当前不支持激活。

WebApp 开启访问认证时依赖有效 Console 身份及空间授权；关闭时允许匿名，不放开 Console 管理权限。普通 Cookie / CSRF 的 Console 链路、标准 WebApp Passport、Service API Bearer 密钥三种入口应按各自协议使用。

遗留转发令牌组件尚未挂载当前系统管理页面；跨空间模型同步服务无有效调用方，不作为当前可用产品功能。

## 部署与数据扩展

| 扩展面 | 当前实现 | 维护责任 |
| --- | --- | --- |
| fork Compose | `docker/docker-compose.dify-plus.yaml`；fork API / Web / Agent 镜像、扩展消费者、可选完整沙箱、专用 WebSocket、双迁移任务 | 配套镜像、配置映射、网络和队列 |
| 配置分层 | `.env.example` 保留启动必需项；可选参考位于 `docker/envs/`；fork 使用显式环境映射 | 未映射配置经 override 注入，不能只复制服务 env 示例 |
| 双数据库迁移链 | `api/migrations/` 与 `api/migrations_extend/`；唯一迁移服务按上游 → 扩展顺序执行 | 数据审计、兼容路径、迁移失败恢复和双版本记录 |
| 初始化空间关联 | 初始化时保存空间关联，已有安装通过扩展迁移回填 | 不通过名字或固定 UUID 选择管理员空间 |
| 持久化密钥 | `SECRET_KEY` 可显式设置或由 `init_secret_key` 生成存储到 `.dify_secret_key` | 串行初始化、共享存储和备份 / 轮换 |
| 镜像发布 | GitHub Actions 将 API、Web、Agent 后端及 Agent 本地沙箱发布至 GHCR，构建目标为 amd64 / arm64，构建上下文为仓库根 | 源码、锁文件、镜像 digest 和运行身份一致 |
| 工作流归档 | V2 Parquet bundle、manifest、索引回填、恢复与独立校验后删除；自托管 CLI 与 Cloud 下载 API 分开 | `commands/retention.py`、`services/retention/workflow_run/` |
| 文档索引运维 | 暂停、状态修复、重跑和批量控制脚本 | 先定位故障与范围，再备份、处理与读回 |
| 前端扩展词条 | `web/i18n/*/extend.json` 与 typed-selector 国际化体系 | 页面能力与翻译保持一致 |

## 开发定位与回归范围

| 目录 / 挂点 | 关注范围 |
| --- | --- |
| `api/controllers/console/`、`api/controllers/web/`、`api/controllers/service_api/` | 管理权限、登录准入、Cookie / CSRF、WebApp 身份和密钥限额 |
| `api/core/app/`、`api/core/memory/`、`api/events/`、`api/tasks/extend/` | 账号 / 密钥归因、节点事件、usage、记忆控制、扣费任务 |
| `api/models/*extend.py`、`api/migrations_extend/` | 扩展数据、关联完整性、schema 及升级 |
| `web/app/`、`web/service/`、`web/context/` | 应用中心、登录、余额、密钥额度、系统管理、空间切换后的权限 |
| `docker/`、`api/docker/entrypoint.sh` | 同版镜像、密钥初始化、双迁移、WebSocket、后台消费者和调度 |
| `scripts/` | 数据修复选取范围、队列状态和实际索引结果 |

Controller 数据操作遵循当前上游的 session 注入规范，扩展任务需要明确队列和对应消费者。工作流协作、Human Input、文件权限、插件和 Agent 主体虽属于上游能力，fork 的身份、运行归因与交付配置会与它们交汇，回归时需覆盖实际业务。

镜像流程与验收门槛见[容器镜像发布与多架构部署](./容器镜像发布与多架构部署.md)。配置和运维细节见[部署与运维](./二开部署配置与运维说明.md)，服务和数据流见[整体架构](./整体架构图.md)。历史升级 / 验收记录由[文档索引](./README.md)单独导航，不能替代当前生产部署事实。
