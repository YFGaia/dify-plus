## 5. 结构性重构识别

1. **后端 controller 层 `with_session` 化 + Pydantic 深化**（影响挂点 5/6）：
   `apikey.py`、`datasets.py`、service_api 各 controller、`tags.py`、`workspace.py` 等把
   `db.session` 全面替换为装饰器注入的 `session`。fork 所有在这些文件里的挂点重挂时必须改用
   注入 session，禁止再引 `extensions.ext_database.db`（上游还新增了 ast_grep 守卫

## 7. 风险与建议（给 Phase 2 执行者）

**建议解决顺序**：

1. **先机械后语义**：先解 §6.1 策略性文件（README、锁文件、pyproject/package.json、oxlint），
   再解生成物类，压缩冲突面。
2. **后端从挂点最重的 `apikey.py` 开刀**：整体取上游 `with_session` 新版，再把 `ApiKeyItem`
   额度字段、LEFT JOIN、POST 额度记录、`put()`、软删逐段重写为 session 传参风格；随后连带
   `datasets.py`、两个 apikey/datasets 单测一次做完。
3. **generator 三连**（chat/agent_chat/completion）用同一模式批量处理：取上游 + 在
   `_init_generate_records(...)` 之后原位插回 join 写入（用注入 session）。
4. **service_api 7 个 controller** 同一模式批量处理：取上游新签名 + `api_token` 末位参数重挂。
5. **web 端先解数据层再解组件**：`client.ts`/`explore.ts`/`system-features` → contract 迁移决策
   （见 §5.6，建议在合并记录中单列一条决策）→ main-nav/app-card/explore 组件 → signin 系列。
6. **modify/delete 七件**不要恢复旧文件，一律按 §6.4 的去向迁移。
7. **直接取上游后重跑生成**：`pnpm-lock.yaml`（pnpm install）、`api/uv.lock`（uv sync）、
   `packages/contracts/generated/**`、icons、`oxlint-suppressions.json`、上游 i18n 文件。
8. **合并后立即补做的非冲突项**（自动合并 ≠ 完成）：
   - fork 全部 web 文件的 **i18n typed-selector 迁移**（§5.7，约 112+ 处，可脚本化）；
     `extend.json` 命名空间接入 `locale-resources` 生成清单；
   - `docker/docker-compose.dify-plus.yaml` 移植 `agent_backend`/`local_sandbox` 服务与
     `AGENT_BACKend_*`/`DIFY_AGENT_*` 变量（§4.4）；
   - `OaOAuth.get_authorization_url` 补 `redirect_url` 参数；
   - fork 各处对 `generate()` 的调用补 `session=` 实参（含 `app_generate_service_extend`）。

**预计工作量最大的 3 个文件/文件簇**：

1. `api/controllers/console/apikey.py`（+ `datasets.py` + 两个单测）——挂点 6 在 `with_session`
   重构上的整体重写；
2. `web/contract/**` + `web/service/client.ts` 簇——fork 契约注册机制随上游删除整个手写契约层
   而失去宿主，需要架构级决策 + 迁移（连带 `system-manage-extend` 代码执行控制页、
   login_config 双阶段链路）；
3. `web/app/components/apps/app-card.tsx`（fork±138 / 上游±881）——模板同步/卡片状态挂点在上游
   大改版上的重挂（其次是 `signin/normal-form.tsx` 与 `secret-key-modal.tsx`）。

**Phase 2 最危险的 3 个点**：

1. **web 契约层地基被抽走**（§5.6）：`web/contract/` 整目录删除 + `app-context` 删除是
   modify/delete，git 不会帮你合并，处理不当会让系统管理三页、login_config 链路、双角色导航
   静默失效——而且构建能过的情况下部分问题只在运行时暴露。
2. **i18n optimize 模式让 fork 旧式 `t('key')` 全量失效**（§5.7）：自动合并全绿，但 fork 组件
   文案会在运行时丢失；必须当成合并任务清单的一等公民，不能依赖冲突提示。
3. **挂点 4/6 的 session 化重挂**：三个 generator 与 apikey 冲突点都恰好落在 fork 插入行上，
   重挂时若沿用旧 `db.session` 写法会踩上游新 lint 守卫且可能产生事务语义错误（双 session 写
   同一记录）；重挂后必须跑 fork 计费单测 + 上游对应单测。
