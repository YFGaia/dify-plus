## Restore procedure (prepared, not executed)

Restoring places old tests back in executable pending state. First stop only this project's
worker and confirm there are no active/unacked tasks. Do not restart the consumer until
the disposition of the restored old requests is decided.

1. Stop container `difyplus-upstream1171-quota-selftest-20260930-worker-1`.
2. Run the prepared script in the existing API container:

```sh
docker exec -i -w /app/api \
  difyplus-upstream1171-quota-selftest-20260930-api-1 \
  /app/api/.venv/bin/python - \
  < /private/tmp/difyplus-performance-20260930/restore_debug_hold.py
```

The script requires the source queue to be empty and the holding queue to contain exactly
the three known same-app tasks with their original hashes. Lua rechecks exact queue state
and content before atomically moving complete envelopes back with original relative order.
It verifies source=3, holding=0 and all original hashes unchanged. It never reads/prints
unrelated payloads and never flushes Redis. The restore script has only been syntax checked.
