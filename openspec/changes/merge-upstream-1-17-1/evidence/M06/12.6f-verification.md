## Implemented behavior

The three charts `daily-conversations`, `token-costs` and `average-app-interactions` accept optional boolean `account`, defaulting to false. Account identity comes only from Console admission's `RequestContext.account_id`. The request model forbids extra query fields, including forged `account_id` and `from_account_id` (422).

The service passes one optional `account_id` to each repository method. SQLAlchemy joins `workflow_run_account_extend` using run ID, tenant, app and account, with the actor bound as a SQL parameter. Logstore adds one escaped actor predicate before aggregation, including inside the interaction subquery. Missing/NULL ownership is excluded from personal results. Absent/false scope preserves app-wide results and does not add an ownership filter. `daily-terminals` retains its original model and behavior.

Consolidation removed duplicated protocol documentation and corrected Logstore query indentation. No duplicate account arguments or predicates remain. Tests in the inherited partial patch were formatted, typed and repaired to supply required App fields. The new HTTP fixture uses the actual Account model with its supported constructor.
