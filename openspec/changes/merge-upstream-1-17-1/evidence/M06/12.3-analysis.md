# M06 12.3 API key quotas and account balance analysis

## Findings

- The shared API key modal/table only create/list/delete app, dataset and environment keys; it does not expose app quota creation/editing or quota columns (`web/app/components/api-key/api-key-modal.tsx:122-157`, `api-key-table.tsx:34-91`). The app endpoint already supports description and daily/monthly limits, old-key defaults, and `-1` unlimited (`api/controllers/console/apikey.py:63-86,166-188,229-282,390-417`). Generated app create requires a quota payload, which the current modal omits (`packages/contracts/generated/api/console/apps/types.gen.ts:6638-6669`).
- Dataset list/bindings do not join or persist quota (`api/controllers/console/datasets/datasets.py:1117-1178`); environment has no quota contract (`research/contract-matrix.md:C11`). Do not render or submit quota controls for either scope.
- Account balance is separate from per-key usage. `/account/money` is an account-level endpoint (`api/controllers/console/workspace/account_extend.py:13-28`); generated routing exists but its response is unknown-shaped, so validate `total_quota`/`used_quota` before caching. `account-money-extend.tsx` currently reads the public snapshot's 7.26 fallback and is not mounted in MainNav. Use `consoleQuery.account.money.get` and parse at the query boundary.
- Exchange rate must come from `loginConfigQueryOptions({accountId, workspaceId})` (`web/features/system-features/client.ts:16-37`), using profile id plus current workspace id. A 403 or parse failure must not fall back to public snapshot (`features/system-features/extend.ts:35-45`).
- Agent v2 uses a separate host: its list may return app-backed quota data, but generated create has no request body and no Agent PUT exists. This task will not add quota editing to Agent v2 or invent a backend contract.

## Registered implementation paths

1. `web/app/components/api-key/api-key-modal.tsx` — app-only quota payload and supported edit flow; preserve dataset/environment request shapes.
2. `web/app/components/api-key/api-key-table.tsx` — show returned app quota/use only for app scope.
3. `web/app/components/api-key/__tests__/api-key-modal.spec.tsx` — creation/edit, old-key defaults, unlimited and scope isolation.
4. `web/app/components/main-nav/components/account-money-extend.tsx` — validate account money before cache and use configured login_config exchange rate.
5. `web/app/components/main-nav/index.tsx` — mount personal balance in existing nav host.
6. `web/app/components/main-nav/__tests__/index.spec.tsx` — balance identity, rendering, and nav integration.

New quota form/parser files or Agent v2 paths are not authorized by this registration.

## Focused acceptance cases

- App create sends explicit supported quota body; edit uses supported PUT only; successful mutations invalidate app-key list.
- App table distinguishes accumulated/day/month usage and limits; `-1` renders unlimited; legacy response defaults remain safe.
- Dataset/environment modal has no quota input/body changes.
- Account money remains separate from app-key quota and Cloud workspace credits.
- Non-default login_config rate is used; anonymous identity, config 403/invalid response and account/workspace switching cannot reuse a public fallback or another identity's cached config.
- Account money unknown-shaped response is parsed before query cache.

Unknown product policy: zero/negative configured exchange rates and whether Agent v2 needs read-only quota visibility.
