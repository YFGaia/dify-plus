## 发现

1. **应用中心挂载断链**：`web/app/components/explore/app-list-center-extend/index.tsx:17,28` 调用当前已不存在的 `useInstalledAppList`，数据加载失败；该页面仍由 `/explore/apps-center-extend` 路由挂载。
2. **标签筛选类型不一致**：`TagFilter` 用 `TagResponse.id` 作为选中值（`web/features/tag-management/components/tag-filter.tsx:44,64`）；fork `/installed/apps` 每行只返回标签名称 `category`（`api/services/recommended_app_service_extend.py:54,77`；`api/fields/app_fields_extend.py:25`）。当前把 ID 与名称直接比较，筛选结果为空。M06 应使用已有 `consoleQuery.tags.get` 数据建立 id→name 映射，再筛选；对多标签重复行按 `app_id` 去重。
3. **installed API 运行时边界**：fork `/installed/apps` 响应为 `{categories: string[], recommended_apps: row[]}`；row 含非空 `app_id`/`installed_id`、单数 `category`、`app` 基本信息和描述字段。当前生成 Zod 输出仅为 `z.record(z.string(), z.unknown())`（`packages/contracts/generated/api/console/installed/zod.gen.ts`），不足以验证导航数据。应在 `web/service/explore.ts` 使用本地 Zod schema，并在 queryFn 返回、写入 TanStack 缓存前 parse 必需字段；`GET /installed-apps` 是上游另一接口，分页 `installed_apps` shape 不同，不可混用。畸形响应应显示错误态，不要继续显示空白页。
4. **规范路由**：`buildInstalledAppPath(id)` (`web/app/components/explore/installed-app/routes.ts:1`) 返回 `/installed/:id`；旧 `/explore/installed/:id` 仅保留兼容 redirect。卡片导航应调用 helper。
5. **Studio 同步菜单的新宿主**：旧 fork 卡片的同步/取消同步使用 workspace manager + `admin_extend` + `tenant_extend` 条件，调用 `PUT/DELETE /apps/{app_id}/sync`；新宿主是 `web/app/components/apps/app-card/interactions.tsx`，现有 `consoleQuery.apps.byAppId.sync.put/delete` 已包含生成契约。保留旧 UI 条件，后端以 super-admin ID 作最终授权，并在成功后失效 app list query。
6. **同步状态是跨 owner 阻碍**：`AppPagination.recommended_apps` 已出现在生成契约，但 `api/controllers/console/app/app.py:702` 永远写入 `[]`；上游 `/explore/apps` 是内置/远端 catalog，不能用它推断 fork 同步状态。按 overlap 台账，`api/controllers/console/app/app.py` 的 owner 是 M03。M03 follow-up 需在当前页 app IDs 范围内查询 `RecommendedApp`，填充现有 `recommended_apps: string[]`，并用既有 `api/tests/unit_tests/controllers/console/app/test_app_response_models.py` 覆盖同步项/未同步项与页范围；不改 schema/generated 文件。
