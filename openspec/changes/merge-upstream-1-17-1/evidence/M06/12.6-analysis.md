## Personal overview route

Keep `user_overview_extend` direct-only for now; neither the old fork nor current navigation showed a menu link, so adding navigation would invent product behavior. However, the route was part of the old manual acceptance list and currently cannot be accepted as correct personal statistics:

- Its page sets `account: true` for ranged queries, but the all-time branch drops the query entirely.
- Current app and workflow statistics request schemas and generated types expose only `start/end`; requests return app-wide statistics.
- Historical account filtering in the old fork was incomplete, so it is not a safe behavior contract to copy. Identity filters must be resolved server-side from the authenticated account, never accepted as a caller-selected account ID.
- The page synchronously destructures route `params`, while the neighboring 1.17.1 page awaits Promise params. The `[appId]` layout checks `canMonitor` for `/overview` but not this route.

The separate Sol backend contract audit is complete. The six charts currently rendered by this page require six endpoints to support account scope: app daily conversations, average session interactions, and token costs; workflow daily runs, token costs, and average app interactions. Add optional `account=true` to these specific endpoints only, keeping the default app-wide semantics unchanged. Resolve identity only from authenticated `RequestContext.account_id`; never accept an account identifier from the request. The all-time page query must retain `{account: true}`.

For ordinary app data, `from_account_id` is the trusted filter source. Do not use `EndUser.external_user_id`: WebApp binding may leave the generic `enterpriseuser` value, and external IDs are not trusted account ownership. For WebApp workflow runs, trusted account ownership is not currently persisted in either SQLAlchemy or Logstore; `created_by_role + created_by` records the EndUser, not the Console account. Complete isolation therefore requires an explicit trusted account actor field propagated on writes and queries in both stores. Historical rows without that field must not be attributed by inference. Current query layers are `app_statistic_query.py` / `app_statistic_query_repository.py` and `workflow_statistic_query_service.py` / `api_workflow_run_repository.py` (SQLAlchemy and Logstore). The controller routes are `statistic.py` and `workflow_statistic.py`. Generated Console OpenAPI and apps types/Zod/oRPC outputs remain owned by M08.

Analysis handoff path owners: M04 owns statistics controllers and query services/repositories; M02 owns workflow model/persistence changes; M03 owns authenticated account identity propagation where it crosses WebApp auth; M05/M08 own contract generation and final contract review; M06 owns the page, layout guard, and front-end behavior specs. Before implementation, register each exact changed file and its paired tests under those owners. The parent node stays open until identity isolation, permission behavior, and all-time queries are verified.
