## Findings

### P2 — GitLab multi-architecture manifest inputs are not reliably transported

In `.gitlab-ci.yml`, `build-api-amd64` and `build-api-arm64` both append to `manifest_api.txt`; the Web architecture jobs both append to `manifest_web.txt`. The later `create-manifest-*` jobs declare `needs` on the builders and read those files, but producer jobs declare no `artifacts`. GitLab jobs run with separate workspaces, so the consumer files are not guaranteed to exist. If same-name artifacts were later added without unique paths, architecture files could collide. No GitLab pipeline was run, so this is a static CI risk, not evidence of a failed/working pipeline.

**Action:** keep 13.6 open and implement a minimal fork-only `.gitlab-ci.yml` correction. Prefer constructing the manifest from the explicit per-architecture image tags already pushed by each build job; this removes cross-job text-file transport and the collision rather than adding an artifact mechanism.
