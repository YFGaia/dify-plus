# 全新 MySQL 安装兼容修复

开发者：Sol 6.1 子代理 `mysql_fix`；协调者已核对源码差异和清单。起始 HEAD `db2f338ee1`，本轮所有依赖锁修改均保持未触碰。

## 根因与修复

原空 MySQL 8.0.46 在扩展首 revision 以 error 3770 失败。`StringUUID` 仅将 PostgreSQL UUID 类型变为 MySQL CHAR(36)，未将 `uuid_generate_v4()` 默认表达式转换为 MySQL 函数。13 个相关 revision 的20处 UUID 默认值在 MySQL 采用 `(UUID())`，其他方言原表达式保持。数据库端自动生成 ID 保留，避免 ORM 插入依赖默认值失效。

同时处理后续空库解析阻断：004 TEXT 默认的 PostgreSQL cast；012 `DISTINCT ON` 以 MySQL 8 window 派生表实现去重（NULL排序保持、时间并列以id排序）；016/018 DROP 和017 reserved column引号由 dialect 引用器生成。018仅为MySQL增加空分类表重建分支；这不是数据恢复保证。

16个版本文件和1个定向测试变更。20个revision/down_revision/branch_labels/depends_on AST与起始HEAD一致，head仍为 `020_workflow_run_account`。文件清单见 `28.1-versions.sha256`，清单SHA256 `ccd43abd29650fa05543d3a367a83b1f20a7d44c0e54452e77f4f20e67cb51d7`；测试SHA256 `3b9e51936d777df0972cd4ce2bcd95097c601de58029a90ca339d88325f42135`。
