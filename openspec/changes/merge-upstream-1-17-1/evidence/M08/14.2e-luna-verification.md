## 边界审查结论

- **权限边界（源码审查）**：组件将 workspace manager 身份与调用方 `canManage` ACL 相与，供 App Key query、disabled 状态及 modal 子树共同使用；非 manager 提前返回 `null`。这是符合 Astra 所述双重授权意图的实现。运行结果没有验证 manager 正向路径，也未验证撤销权限时已打开 modal 的卸载，因此独立验证状态为 **未通过 / 需修复测试 setup 后复验**，不能据源码审查宣称行为验收通过。
- **Query 边界**：未授权时传入 `skipToken`；environment scope 不请求 App Key 列表并使用调用方传入 count。spec 的 editor 两例通过，支持非 manager 隐藏入口且不请求的拒绝路径；manager 正向 query 和 ACL 拒绝断言所在的按钮不可用，因此仍未被验证。
- **Modal 边界**：只有双重权限均成立时才挂载 `ApiKeyModal`，源码注释及实现可将权限撤销与已打开的嵌套管理对话框一并卸载。但对应的 manager 打开和撤权两例失败在更早的按钮查询处，故此行为尚无测试证据。本 spec mock 了 `ApiKeyModal`，不能证明实际 CRUD、配额子组件或对话框内部行为。
- **失败线索**：spec 通过 `renderWithConsoleQuery` 提供 current-workspace query 数据，但 `workspace-state.ts` 的角色 atom 由 `atomWithQuery` 所持有的 query observer 提供。实际运行时它未读到 manager 角色，导致组件返回 `null`。这与失败用例的空 DOM 一致；本次按只运行和报告的授权范围，没有修改 setup 或再执行其他测试来确认修复。
