The upstream configuration hook decomposition omitted the fork's retention-number state, loader assignment, context value/setter, and model-config publish field. The existing `retention-number-extend` control still reads that context, and app detail still supplies `retention_number`.

The publish callback depends on the current retention number, so edits are sent without a stale closure. The lower-level handler retains its optional input for existing callers. The configuration test's generated query-cache fixture also now supplies required `webapp_auth_enabled_extend: true`.

The change is limited to retention configuration and the affected fixture. It does not establish browser/live-backend acceptance or candidate-wide V02 acceptance.
