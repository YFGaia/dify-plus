## 边界验证结论

- **Manager 角色**：owner 和 admin 正向用例通过，按钮可用、App API Key 查询边界被触发，且可打开传入 `canManage=true` 的 modal。editor 在 app 与 environment 两种 scope 下均无按钮/modal、无 API Key 请求。修正后的 schema 有效 workspace fixtures 因而覆盖了 manager 允许路径和角色拒绝路径。
- **ACL 与 query**：Access Point ACL 为 false 时按钮禁用、点击不打开 modal，且不请求 API Keys；这与 workspace manager 身份门槛共同构成组件边界。Environment scope 使用提供的 key count 并打开 environment-scoped modal，不请求 App key 列表；disabled 状态也保留当前 count 并禁用按钮。
- **Modal 与撤权**：manager 可打开 modal；workspace role 撤销及 Access Point ACL 撤销两个场景均在权限变化后关闭/卸载已打开的管理 modal。组件把有效权限传给 modal，并在 workspace manager 身份失效时移除入口。
