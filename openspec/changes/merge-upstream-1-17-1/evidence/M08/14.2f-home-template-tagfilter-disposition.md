# M08 14.2f：Home 模板 TagFilter 数据契约处置

## 核验事实

- Dify-Plus 基线 `b17761ed0166e8ef49474da418b95a9462adbb9c` 的 `web/app/components/explore/app-list/index.tsx` 把 `TagFilter type="app"` 的 `tagFilterValue` 直接用于 `item.categories?.some(category => tagFilterValue.includes(category))`。
- 当前 `web/features/tag-management/components/tag-filter.tsx` 为选中的标签返回 `Tag.id`；标签显示名称是 `Tag.name`。
- 当前上游推荐模板响应由 `api/controllers/console/explore/recommended_app.py` 定义，`RecommendedAppResponse.categories` 和列表 `categories` 都是 `list[str]`。候选 `HomeContent` 按推荐模板返回的 category 字符串筛选；没有标签 ID 字段或 ID→category 映射。
- 已安装应用列表是另一份数据：其 App TagFilter 由工作区标签 ID 过滤本地已安装 App。它不能作为推荐模板 catalog 的替代，也没有被本次迁移删除。

## 处置

基线 Home 控件比较 UUID `Tag.id` 与推荐模板自由 category 字符串。没有 ID/name 映射或 API 契约证明两者一致，因此该旧控件没有可证明可工作的筛选行为；不把删除它记为丢失的有效功能，不恢复错误比较。

候选继续保留 Home 推荐模板的 category 与文本搜索，并继续保留已安装应用列表的独立 TagFilter。若以后要让工作区 Tag 筛选推荐模板，须先由目录/API owner 定义 catalog item 与 workspace Tag 的稳定关联字段，再在 HomeContent 新宿主实现和测试；不能靠 UI 将两组字符串猜测匹配。

## 范围

只读源码处置；没有改代码、测试、所有权表、图、结果、任务清单、Git index 或执行测试。源路径、候选响应 schema 和标签控件引用均可从本报告记录的位置复核。
